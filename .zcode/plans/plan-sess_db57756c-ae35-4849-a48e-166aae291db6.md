# Plan: Spotify-powered music player (shared owner-account model)

Your answers applied: you have Premium, and visitors play through YOUR Spotify account (no per-visitor login). That choice shapes everything below.

## 1. How it will work (important consequences of your choice)

- The site authenticates once as YOU (Authorization Code + PKCE, no client secret needed). Your refresh token is baked in via `--dart-define` (same pattern as the email credentials). Every visitor's browser silently refreshes it into a short-lived access token and plays music through the Spotify Web Playback SDK as one of your devices.
- Three things you accept with this model: (a) the refresh token ships inside the public web bundle, so treat it as extractable — minimal scopes only (listed in §3), never commit it, and you can revoke/regenerate it anytime from the Spotify dashboard; (b) Spotify plays ONE stream per account, so a visitor pressing play pauses music on your phone/speaker and vice versa; (b2) playback must start from a click (the dock icon counts, so we're fine); (c) the SDK runs only in real browsers — tests will mock it.
- Resilience: if the token is missing/invalid or Spotify is unreachable, the player falls back to the current 3-track simulated playlist so the site never looks broken.

## 2. What YOU need to set up (I can't do these for you)

1. Go to developer.spotify.com/dashboard, log in, Create app. Name it anything (e.g. `jent-web-player`). Copy the **Client ID**.
2. In the app's Settings, add Redirect URIs (exact match, Spotify is strict): `http://localhost:8080/callback` for local dev, plus your production URL + `/callback` later (e.g. `https://yourdomain.com/callback`). Save. (`localhost` is the only non-HTTPS exception Spotify allows.)
3. Tell me the Client ID (paste it here) — I'll wire it as `--dart-define=SPOTIFY_CLIENT_ID=...`. Also decide which of your playlists should be the default list, and send its playlist ID (open the playlist in Spotify → Share → Copy link; the ID is the part after `/playlist/`).
4. Run the site locally once with the Client ID, open the temporary `/spotify-setup` page (part of the build, §4 Phase 4), click Connect, approve the permission screen. The page shows a **refresh token** — copy it, then close the page. That route is dev-only and gets removed before production.
5. Add to your local run: `--dart-define=SPOTIFY_REFRESH_TOKEN=<that token>` (I'll add both defines to `.vscode/launch.json`). I'll also add `.env` to `.gitignore` — right now it is NOT ignored, so secrets would be committed.
6. Requested scopes (minimal set, shown on the approve screen): `streaming user-read-email user-read-private user-read-playback-state user-modify-playback-state playlist-read-private`. Nothing that touches your email content, library edits, or profile writes.

Credentials explained: Client ID = public identifier, safe to ship in the bundle. Refresh token = the key to your account's playback — lives only in your local launch config and the built bundle, never in git; if it ever leaks, revoke it in the dashboard and repeat step 4 (takes 2 minutes).

## 3. Implementation phases (all in existing MVVM structure)

- **P1 packages:** add `http` (REST: search, playlists, player control) and `url_launcher` (open Spotify approve screen from the setup page). No audio package needed — the SDK plays the audio.
- **P2 data/domain/DI (mirrors the email pattern):** `domain/entities/spotify_track.dart` (`id/title/artist/artworkUrl/duration` replaces `MusicTrack` in UI; old static list stays as fallback), `domain/repositories/spotify_repository.dart` (interface: `searchTracks`, `getPlaylistTracks`, `play/pause/next/previous`, `playerStateStream`, `ensureConnected`), `data/datasources/spotify_api_datasource.dart` (token refresh + Web API calls), `data/repositories/spotify_repository_impl.dart`, thin usecases (`SearchTracks`, `PlayTrack`), all registered in `lib/di/injection.dart` via `@Named` dart-defines + `build_runner` regen. ALL browser/SDK calls hide behind a `SpotifyWebPlayer` interface (`lib/data/spotify/spotify_web_player.dart`, `dart:js_interop`) so tests inject a fake.
- **P3 web wiring:** add `<script src="https://sdk.scdn.co/spotify-player.js">` to `web/index.html`; JS interop creates the player with a `getOAuthToken` callback (supplies the owner's refreshed token), captures the SDK `ready` event's device ID, transfers playback to it; `player_state_changed` events feed REAL position/artwork into the bloc (replaces the 1s fake timer when connected).
- **P4 presentation (existing components, extended):** expanded view gains a search field reusing `LabeledTextField` + results list (tap row = play that track); artwork shows the track's `artworkUrl` via `Image.network` with the current asset as fallback; vinyl/equalizer keep working off `isMusicPlaying`; new `HomeState` fields `spotifyStatus (disconnected/connecting/ready/error)`, `spotifyTracks`, `searchResults`; new l10n keys in both arbs (`musicSearchHint`, `musicSearch`, `musicNoResults`, `musicConnectError`, `musicLoginPrompt`); existing window controls/dock/mini-bar behavior unchanged.
- **P5 router + setup page:** temporary dev-only `/spotify-setup` route (PKCE: generate verifier/challenge, redirect to accounts.spotify.com, `/callback` route reads `state.uri.queryParameters['code']`, exchanges code+verifier for tokens, displays refresh token). Note: `routerNeglect:true` + path URL strategy stay as-is — query params are still readable via `state.uri`. Remove the setup route before production.
- **P6 tests:** bloc tests with mocked repository (search returns fixtures, token failure → fallback playlist, play/select/next/prev parity with existing music tests); keep the drag widget test; SDK wrapper excluded from tests by interface. `flutter analyze` + `flutter test` + `flutter build web` green.

## 4. Acceptance
Clicking the dock music icon opens the player already connected as you; the list shows your chosen playlist; search finds any Spotify song and plays it in-browser with real progress; logged-out visitors get all of this with zero login screens; broken/missing token degrades to the old simulated playlist; no secret is committed to git.
